# Evaluation report -- PHI/PII de-identification gateway

Generated by `eval/report.py`. Every number here comes from `eval/results.json`
(`python eval/harness.py`) and, where present, `eval/ablation.json`
(`modal run training/modal_app.py::ablate`).

**Leak rate is the headline compliance number** -- the fraction of notes with at least one
missed identifier. Recall is reported beside it, and precision *at* that recall rather than
instead of it: a false negative is a breach, a false positive is an inconvenience.

Matching is character-overlap plus category, not exact boundary equality -- a mask covering
more than the gold span has leaked nothing. Boundary tightness is reported separately as
`exact`.

## Hand-authored adversarial split (scored separately)

Everything in the table above came out of `training/data/gen_notes.py`, so scoring the tagger on it partly measures how well it learned that generator. These 14 notes were written by hand -- one trap per line, no shared code with training: eponyms in both senses (Parkinson, Crohn, Hodgkin, Bell), surname==facility (Wood / Wood Memorial), providers with no `Dr.` cue, an ALLCAPS form-field table, ages at and over 89, a birth year that *implies* an age over 89, clinical vocabulary that reads as PHI (Fahrenheit, Foley, Braden, APGAR, ICU-4B), and one note that is a pure negative. Gold spans are resolved from literal surfaces at build time, so an offset cannot silently rot; `data/test_set/handauthored.py` refuses to build otherwise.

Two columns, because they answer different questions. `leak rate` counts a note as leaking if any gold span went unmatched -- **including a span the system masked under a different category**. `uncovered` counts only notes where a gold identifier has *no* overlapping prediction at all, i.e. plaintext PHI actually reaching the LLM. The gap between the two is taxonomy disagreement, not breach.

| system | recall | precision | leak rate | uncovered | p50 ms |
|---|---|---|---|---|---|
| gateway | 0.9178 | 0.8072 | 0.2143 | 0.1429 | 431.3 |
| regex_only | 0.6849 | 0.9091 | 0.7143 | 0.7143 | 2.2 |

The acceptance gate asked for leak rate 0 here and it is not met; reporting the real number. What survives on the gateway, all of it diagnosed:

* **Lowercase, unpunctuated address** (`18 saltmarsh lane wexford hollow ma 02139`) -- street, city and ZIP all missed. The tagger sees titlecase geography in training and the ZIP rule wants a cased state token beside it. This is a training-distribution gap, fixable by casing augmentation, not by another word list.
* **`ATTENDING: BRIGHTWATER, DEVON`** -- `attending` is in `FIELD_KEY_CATEGORY`, so the field cue is present; the `LAST, FIRST` value in an ALLCAPS column is what is not being read as a name.
* **`Bell`, the charge nurse**, in a note that also contains Bell's palsy. The hardest case in the file by design, and the one an eponym list cannot fix: the same token is a person and a disease three lines apart.
* **Bare 10-digit phone** `4135550172` -- masked, but as `ID_GENERIC`. It counts against leak rate and not against `uncovered`, which is the distinction those two columns exist to make.

`regex_only` leaks on 10 of 14 notes with nothing overlapping at all, which is the case for the neural stage stated as a measurement rather than an assumption.

## Utility preservation

The second failure mode: redact too much and the downstream LLM is useless. Interval preservation is checked by arithmetic, not by an LLM -- `interval_preserving` mode emits `[DATE_7 = DATE_3 + 12d]` and the mapping still holds the true dates, so the claimed delta is either equal to the real one or it is not.

| notes | intervals checked | exact | rate | unverifiable | residual date surfaces |
|---|---|---|---|---|---|
| 40 | 152 | 152 | 1.0000 | 0 | 14 |

`residual date surfaces` counts month/day-precision dates surviving in the masked text; Safe Harbor permits the bare year and nothing finer, so this must be 0.
